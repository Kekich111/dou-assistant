# Интеллектуальный помощник по регламентам ДОУ

Хакатон «Финтех Хаб» (Банк России / Центр-Инвест). Команда Data Miners.

Помощник отвечает на вопросы по Инструкции по делопроизводству со ссылкой на пункт, помогает заполнить документы по шаблонам-модулям и проверяет загруженные приказы. Всё работает **локально**: поиск, модель и данные остаются на вашем сервере.

## Что умеет

- Ответ на вопрос своими словами со ссылкой на пункт Инструкции, процентом релевантности и дословной цитатой.
- Честный отказ, если в Инструкции нет ответа («В регламенте Организации нет информации по данному вопросу»).
- Уточняющие вопросы без LLM, если вид документа не ясен («скока дней на согласование» → «Какой документ согласуем?»).
- Сроки (с календарём РФ), маршрут виз по Матрице и вид документа определяются кодом, а не генерацией.
- Диалоговое заполнение 7 шаблонов-модулей и скачивание готового `.docx`.
- Проверка загруженного приказа: пустые поля, даты, сверка с модулем, следующие шаги.
- Версионность Инструкции: загрузка новой редакции, переключение и откат активной версии (страница `/admin`).

## Стек

| Задача | Технология |
| --- | --- |
| Векторный поиск | Qdrant, эмбеддинги `bge-m3` (Ollama) |
| Генерация ответа | `qwen2.5:3b` (Ollama), только по найденным пунктам |
| Backend | Python 3.12, FastAPI |
| Метаданные, роли, аудит | PostgreSQL 16, SQLAlchemy 2.0 (схема в `backend/app/db/models.py`) |
| Запуск | Docker Compose |

## Структура

```
backend/app/api/     chat.py, templates.py, versions.py   эндпоинты
backend/app/rag/     chunker, ingest, retriever, generator
backend/app/rules/   сроки, визы, уточнения, проверка и заполнение документов
backend/app/db/      схема БД
backend/scripts/     run_eval.py, trap_test.py            проверка качества
data/regulations/    Инструкция (.docx)
data/templates/      7 шаблонов-модулей (.docx), в Git не входят
data/eval/           golden_set.jsonl
frontend/            index.html (чат), admin.html (версии)
```

## Запуск

Требуется Docker и свободные порты из `.env`. GPU не нужен, прототип работает на CPU.

1. Скопируйте `.env.example` в `.env` и заполните значения. Обязательно задайте свой `ADMIN_TOKEN`.
2. Положите шаблоны-модули (`Модуль_*.docx`) в `data/templates/`, Инструкцию в `data/regulations/`.
3. Запустите сервисы:
   ```
   docker compose up -d
   ```
4. Скачайте модели в контейнер Ollama:
   ```
   docker compose exec ollama ollama pull bge-m3
   docker compose exec ollama ollama pull qwen2.5:3b
   ```
5. Проиндексируйте Инструкцию (путь подставьте свой):
   ```
   docker compose exec -e PYTHONPATH=/app backend python -m app.rag.ingest --file /app/data/regulations/<имя файла>.docx
   ```
6. Откройте `http://127.0.0.1:<BACKEND_PORT>/` — чат, `http://127.0.0.1:<BACKEND_PORT>/admin` — версии.

Первый запрос к модели идёт дольше остальных (прогрев), затем ответ LLM занимает порядка 10–40 секунд на CPU. Уточнения, сроки и визирование отвечают за доли секунды.

## Версионность

Страница `/admin` (вход по `ADMIN_TOKEN`) показывает версии Инструкции, позволяет загрузить новую редакцию `.docx` и переключить активную. Бот отвечает только по активной версии, старая остаётся в истории и доступна для отката. Ответы из кэша при смене версии сбрасываются.

Тот же функционал доступен через API: `GET/POST /api/admin/versions`, `POST /api/admin/versions/{version_id}/activate` (заголовок `X-Admin-Token`).

## Проверка качества

```
docker compose exec -e PYTHONPATH=/app backend python -m pytest app/tests -q
docker compose exec -e PYTHONPATH=/app backend python scripts/run_eval.py
docker compose exec -e PYTHONPATH=/app backend python scripts/trap_test.py
```

- 33 автотеста правил, проверок и заполнения.
- Набор из 100 вопросов (факты, ситуации, шаблоны, провокации, вопросы вне темы): ни одного выдуманного ответа в ловушках и вопросах вне Инструкции. Результаты в `backend/scripts/trap_report.txt`. На части вопросов (толкование «до / не позднее», отдельные «можно / нельзя») модель 3B отказывает или отвечает неточно, мы это знаем и закрываем дословной цитатой пункта.

## Безопасность

- Модель, индекс и данные размещены локально, внешних запросов к сторонним API нет.
- Порты сервисов привязаны к `127.0.0.1`.
- Эндпоинты администрирования защищены токеном `ADMIN_TOKEN`; без него они закрыты.
- Схема БД для ролей (admin / user) и журнала аудита описана в `models.py`; подключение авторизации и middleware аудита в планах развития.

## Ограничения прототипа

- Роли и аудит-лог реализованы только на уровне схемы БД.
- Хранение версий и признак активности ведутся в Qdrant; запись версий в PostgreSQL в планах.
- Реестр замечаний (Приложение № 1) и PDF-экспорт не реализованы.
- Обрабатываются текстовые `.docx`; сканы и сложные таблицы — в планах.

## Требования к ресурсам (ориентировочно)

Прототип запускался на ноутбуке/ПК без GPU: `<CPU, ОЗУ — заполните по замерам>`. Для промышленной эксплуатации рекомендуется сервер с GPU или более мощным CPU, чтобы сократить время ответа LLM.
